Data Cleaning

Six-Step Cleaning Pipeline

The raw CSV contained missing values, sentinel errors, invalid strings, and incorrectly typed columns. All issues were resolved before analysis.

01
Handle missing values
CustomerRating (79) · RestaurantRating (75) · DeliveryTime (70) · TipAmount (70) — imputed with column median
294 nulls
02
Replace sentinel outliers
DeliveryTime contained the value 99999 — replaced with median of valid values
median imputed
03
Clean string values in CustomerRating
"INVALID", "N/A" strings found in numeric column — replaced with NaN → then median filled → cast to float64
dtype: float64
04
Fix data types
OrderDate → datetime64 · All financial & rating columns → float64
types corrected
05
Remove statistical outliers
Dropped rows where DeliveryTime > 99th percentile (1,650 min) OR OrderValue < $5
10 rows dropped
06
Reshape payment data with melt()
4 wide payment columns → single PaymentMethod + PaymentAmount columns (long format, filter PaymentAmount > 0)
990 rows · 1:1 map
# Step 3 – Clean string values in CustomerRating
invalid_values = ['INVALID', 'N/A', 'NA', '']
df['CustomerRating'] = df['CustomerRating'].replace(invalid_values, np.nan)
df['CustomerRating'] = pd.to_numeric(df['CustomerRating'], errors='coerce')
df['CustomerRating'] = df['CustomerRating'].fillna(df['CustomerRating'].median())

# Step 5 – Remove outliers
delivery_99th = df['DeliveryTime'].quantile(0.99)
outliers = df[(df['DeliveryTime'] > delivery_99th) | (df['OrderValue'] < 5)]
df_clean = df.drop(outliers.index).copy()   # → 990 rows

# Step 6 – Reshape payments from wide to long
payment_cols = ['CashPayment', 'CardPayment', 'WalletPayment', 'UPIPayment']
df_payment = df_clean.melt(
    id_vars=[c for c in df_clean.columns if c not in payment_cols],
    value_vars=payment_cols, var_name='PaymentType', value_name='PaymentAmount'
)
df_payment = df_payment[df_payment['PaymentAmount'] > 0].copy()

Question 2 — Premium delivery classifier
def is_premium_delivery(order_id):
    """
    Returns True if: DeliveryFee > $5.00  AND  DeliveryTime < 25 min
    """
    row = df[df['OrderID'] == order_id]
    if row.empty:
        return False
    fee  = row['DeliveryFee'].iloc[0]
    time = row['DeliveryTime'].iloc[0]
    return (fee > 5.00) and (time < 25)

Net Revenue & City Analysis

A new derived metric captures true platform revenue after discounts and commission costs.

NetRevenue formula
NetRevenue  =  OrderValue  −  DiscountAmount  −  PromoDiscount  −  (OrderValue × 0.20)

df_payment['RestaurantCommission'] = df_payment['OrderValue'] * COMMISSION_RATE

    df_payment['OrderValue']
    - df_payment['DiscountAmount'].fillna(0)
    - df_payment['PromoDiscount'].fillna(0)

Promotional campaign A/B analysis — paired t-test
# Compare average order value before (Week 1) vs after (Week 3)
before = df_campaign[df_campaign['Period'] == 'Before (Week 1)'] \
             .groupby('RestaurantID')['OrderValue'].mean()
after  = df_campaign[df_campaign['Period'] == 'After (Week 3)'] \
             .groupby('RestaurantID')['OrderValue'].mean()

paired_data = pd.concat([before, after], axis=1, join='inner')
t_stat, p_value = stats.ttest_rel(paired_data.iloc[:,0], paired_data.iloc[:,1])

percentage_change = ((after.mean() - before.mean()) / before.mean()) * 100
Estimated revenue lift from campaign: $−7,228.79 Percentage change in AOV: −13.3% p-value: ≥ 0.05 (not significant) Conclusion: Campaign neither helped nor hurt AOV
  • The paired t-test shows no statistically significant change in average order value following the promotional campaign — the observed −13.3% lift is within noise.
  • Extend the post-campaign measurement window to at least 4–6 weeks before drawing conclusions; short windows under-power the test.
  • Test alternative promo mechanics — bundling, limited-time offers, or minimum spend thresholds — rather than flat discounts that erode AOV.
  • Shift campaign focus from AOV uplift to order volume increase (e.g., free delivery promotions) where the signal is more measurable.
  • Always pair future campaigns with pre/post paired t-tests like this to ensure decisions are grounded in statistical evidence, not raw revenue noise.
